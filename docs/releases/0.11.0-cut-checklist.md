## 0. Transaction law

### 0.1 Repository authority

```text
EffortlessMetrics/ripr-swarm
  product development, convergence, candidate selection, candidate proof

EffortlessMetrics/ripr
  public source, history-preserving integration, release, distribution
```

Never create a public release tag or publish a public artifact from
`ripr-swarm`.

### 0.2 Phase vocabulary

The release advances through these states in order:

```text
swarm_convergence
hard_cut_eligible
candidate_materialized
candidate_qualified
source_frozen
reviewed_join_tree
source_integrated
source_release_ready
public_rc_verified
stable_authorized
stable_published
stable_verified
back_synced
rolling_restored
```

A stage may be blocked, failed, or invalidated. It may not be skipped by
renaming a later receipt.

### 0.3 Evidence vocabulary

Every required row records one of:

```text
passed
failed
limited
not_run
not_proven
infrastructure_tempfail
stale_or_wrong_subject
incomparable
not_applicable_with_reason
```

Rules:

- skipped, pending, cancelled, timed out, unavailable, stale, wrong-artifact,
  zero-subject, or incomparable evidence is not `passed`;
- human prose may summarize machine state but may not strengthen it;
- predecessor evidence remains historical unless the owning contract explicitly
  proves it is candidate-independent;
- volatile timestamps and durations are telemetry unless a contract makes them
  identity;
- a product defect changes candidate bytes and requires a successor candidate;
- an infrastructure failure may be retried against the exact unchanged
  candidate, with all attempts retained.

### 0.4 Direct-cut law

```text
CANDIDATE_SHA  = FINAL_SWARM_CUT
CANDIDATE_TREE = FINAL_SWARM_CUT^{tree}
```

There is no candidate-only product patch, exclusion commit, cherry-pick, or
projected tree. Repair or revert unacceptable behavior through ordinary
reviewed `ripr-swarm/main` before the cut.

### 0.5 Actor vocabulary

- **Agent** — an authorized operator or automation session executing routine
  repository work under the linked issue and repository policy.
- **Independent reviewer** — a role that did not solely implement the object it
  judges.
- **Steven** — the owner action required where no other actor has authority.

Owner-only boundaries include:

- explicit authorization to create the new #1609 candidate ref;
- stable per-channel authorization on `ripr#1470`;
- new credentials, secrets, environments, or repository settings;
- any temporary merge-method or protection exception;
- any action whose owning issue explicitly reserves the actor.

Recorded delegation permits agents to deliver ordinary reviewed PRs and to
execute the guarded J merge when its exact transaction authority is terminal.
It does not grant implicit public or settings authority.

## 1. Operator reset, packet root, and lane hygiene

Complete this section at the start of a release-control session and after any
compaction, handoff, or ambiguous tool result.

### 1.1 Fresh truth

- [ ] Use fresh or freshly fetched `ripr-swarm` and `ripr` checkouts.
- [ ] Verify each `origin` is the expected EffortlessMetrics repository.
- [ ] Fetch branches and tags with prune enabled.
- [ ] Require both primary checkouts to be clean.
- [ ] Record exact `main` SHA and tree for both repositories.
- [ ] Record `Cargo.toml`, `Cargo.lock`, editor manifest, editor lockfile, and
      release-control registry digests.
- [ ] Record current branch protection, applicable rulesets, required checks,
      merge methods, review/thread rules, and bypass actors.
- [ ] Capture every open PR in both repositories with number, base, head SHA,
      draft/merge state, checks, unresolved material threads, owner, and current
      release disposition.
- [ ] Capture the current #2766 selected-claim packet and its digest.
- [ ] Record host, OS, shell, Rust, Cargo, Git, Node, npm, VS Code, and relevant
      external-tool identities for evidence-producing runs.
- [ ] Treat any partial GitHub/API response as `not_proven`; reread rather than
      filling missing fields from memory.

### 1.2 Transaction packet

- [ ] Create the untracked transaction packet root prescribed by
      `docs/RELEASE_TRANSACTION.md`.
- [ ] Keep machine JSON and human Markdown projections derived from one DTO.
- [ ] Store exact input identities, command lines, environment boundaries,
      outputs, digests, failures, retries, invalidators, and non-claims.
- [ ] Keep absolute checkout roots, PIDs, and timestamps outside semantic
      digests unless a contract explicitly requires them.
- [ ] Upload or otherwise durably retain a failed-stage receipt before cleanup
      when that failure is decision-bearing.

### 1.3 One writer and disposable lane law

- [ ] Use one active writer per semantic authority, schema, generated family,
      workflow, lockfile, or heavily overlapping source surface.
- [ ] Read-only scouts and independent reviewers may run in parallel.
- [ ] A waiting CI lane parks only that lane; another independent selected
      claim may proceed.
- [ ] Do not mutate a worktree while local proof processes are reading it.
- [ ] Use lane-specific target/build directories for concurrent work.
- [ ] Do not place shared compiler-cache temporary state inside a disposable
      worktree.
- [ ] Before removing a lane, terminate owned Cargo/rustc/Node/VS Code/child
      processes and release file handles.
- [ ] Stop or restart `sccache` before deleting a worktree when its server temp
      directory points into that lane.
- [ ] After merge, supersession, or abandonment, remove the worktree and local
      branch, prune worktree metadata, remove lane build caches, and verify only
      the primary checkout and genuinely active lanes remain.
- [ ] Preserve evidence before deleting scratch repositories or temporary
      fixtures.
- [ ] Never delete another lane's branch, worktree, cache, or retained evidence
      merely to make the host look clean.
