# ripr 0.11.0

ripr 0.11.0 makes the path from a changed behavior to one focused test clearer
and more honest. `ripr check` selects one bounded next action—or names why no
action is justified by the available static evidence. When a repair route is
complete, its packet carries the related test, allowed edit surface,
verification route, and before/after receipt.

ripr remains static analysis. It does not run mutants, generate whole tests, or
claim runtime test adequacy.

## Start with one change

- `ripr check` is the ordinary first-value command. Its default output names one
  selected gap, one safe next action, or an explicit no-action or limited state.
  Use `--format human-full` for the complete evidence and `--format json` for
  machine-readable output.
- `git diff <base>...HEAD | ripr check --diff -` reads a patch from stdin. An
  empty diff is reported as empty rather than as a successful zero-finding
  analysis. <!-- swarm #2655, #2425 -->
- The `explain` and `context` commands printed by `check` retain the selected
  root, diff scope, mode, and finding identity. <!-- swarm #2598, #2659 -->
- Mistyped flags suggest options from the command that rejected them rather
  than leaking unrelated flags. <!-- swarm #2583, #3812, #3786 -->
- `ripr init --dry-run` applies the same validation as the write path and shows
  each planned file action before changing the repository. <!-- swarm #2576 -->
- Advisory commands and generated CI remain non-blocking unless a repository
  explicitly adopts a gate policy.

## One retained repair transaction

- `ripr pilot --root .` guides repository adoption and selects one repo-scoped
  repair when the evidence is complete.
- `ripr agent repair ... --phase before` retains the pre-edit evidence and
  prints the exact attempt-based continuation command.
- A human or external coding agent makes the focused test or fixture edit.
  RIPR does not apply the change.
- `ripr agent repair --attempt <id> --phase after` records post-edit static
  evidence and emits the receipt. Project test execution and static movement
  remain separate observations.
- Interrupted work resumes by repair-attempt identity; ambiguous or stale
  attempts are rejected instead of guessed.

## Stronger test-evidence boundaries

- A test receives strong credit only when it is tied to the changed behavior
  and contains a relevant check. Same-file placement or token similarity alone
  is insufficient. Some findings that were `exposed` in 0.10 may therefore be
  `weakly_exposed` or limited in 0.11, with the reason shown.
  <!-- source #1747, #1751 -->
- Literal Rust `match` arms are credited only when the test input selects the
  arm and the assertion checks its result. Comment text and assertions for a
  different arm do not count. <!-- swarm #3759, #3766, #3767; source #1716, #1723 -->
- When RIPR cannot establish a boundary operand, owner, target, observer, or
  propagation edge, it names the limitation instead of manufacturing a repair.
- Changed parameter and struct-field declarations are classified
  conservatively, and the closing brace of an added `#[cfg(test)]` module no
  longer creates a production finding. <!-- swarm #3755/#3758; source #1722 -->
- Rust test discovery covers configured harnesses and attributes,
  parameterized tests, `cfg(all(test, ...))`, and repository-local `include!`
  fragments within their documented bounds.

## Preview languages

- TypeScript and JavaScript diff analysis recognizes `.ts`, `.tsx`, `.mts`,
  `.cts`, `.js`, `.jsx`, `.mjs`, and `.cjs`, preserving module kind and
  TypeScript/JavaScript counts. <!-- swarm #4094 -->
- Repair eligibility, related-test packet labels, and targeted reruns use the
  same TS/JS extension classification as analysis, rather than excluding modern
  modules through older suffix lists. Recognizing an extension does not make a
  finding repairable: see the TypeScript/JavaScript repair-packet limitation
  under Known limitations. <!-- swarm #4116/#4120 -->
- Python static facts remain preview. Selected pytest/unittest findings can earn
  a bounded repair card only when RIPR has the current owner, related test,
  missing boundary/value/effect, test location, verify command, and edit
  boundary.
- TypeScript, JavaScript, and Python evidence remains preview/advisory. Shipping
  an adapter does not imply Rust parity, runtime execution, support promotion,
  or default gate authority.

## Editor, server, and agent integrations

- The VS Code extension verifies downloaded server manifests and digests,
  limits download size and redirect hosts, and replaces cached binaries whose
  recorded digest no longer matches. <!-- source #1707, #1717 -->
- Server archives are extracted by the extension under file-count, size, path,
  and compression-ratio limits rather than delegated to system archive tools.
  <!-- source #1718 -->
- The language server provides saved-workspace diagnostics, hover evidence,
  pull diagnostics, progress reporting, UTF-16 positions, and a versioned
  diagnostic-code list within the documented support boundary.
- `ripr mcp --stdio [--root PATH]` exposes read-only workspace status to an MCP
  client. It does not analyze, edit files, run verification, or execute
  mutations. <!-- swarm #3088, #3525, #3587 -->
- In `pr-summary`, RIPR renders base and head values as one literal Bash
  argument each, quoting when needed. Repair and verification commands carried
  from input artifacts remain unchanged and should be reviewed before use.
  <!-- swarm #4244 -->
- Supported PowerShell redirect forms write BOM-free UTF-8/LF bytes.
  <!-- source #1705/#1727; swarm #2347/#3966 -->
- Public repository-relative paths use stable forward slashes where required by
  the output contract. <!-- swarm #3869/#3873, #4097, #4113 -->

## Upgrade notes

- Review baselines and any adopted gate thresholds after upgrading: stricter
  owner, activation, observer, and assertion checks can move findings between
  `exposed`, `weakly_exposed`, and limited states.
- The first run after an incompatible cache-generation change re-analyzes rather
  than trusting older cached semantics.
- Tools that consume the server manifest directly must use schema 2.
- A repair attempt created by an older binary cannot be re-receipted as a 0.11
  attempt. Start a new transaction with 0.11.0.
- Internal errors exit with code 2. Git calls have a bounded default timeout and
  can be constrained with `--git-timeout` or `RIPR_GIT_TIMEOUT`.

## Known limitations and non-claims

- RIPR does not run mutants or report runtime mutation outcomes. Mutation
  testing remains the runtime backstop.
- The repair transaction does not run your project's tests. The `--phase after`
  receipt records static evidence movement only, so a new test that fails
  `cargo test` can still show `improved`. The receipt says
  `verification.status: "verification_not_run"`, and its next step tells you
  to run the focused test and keep it only if it passes.
  <!-- #3797 Stage A control 6; ADR 0021; swarm #4242 (bb71162),
  output/agent_receipt.rs -->
- The Rust repair transaction is `usable alpha`: the package, editor, bounded
  packet, and before/after paths exist when RIPR emits a complete route, while
  broad real-repository route yield and ordinary-user success remain under
  measurement.
- Preview-language evidence does not gate by default or claim parity with Rust.
- Generated CI is advisory by default. MCP is read-only. The language server
  does not grant source-edit or autonomous verification authority.
- Python does not resolve a module-level named constant used as a comparison
  threshold, such as `if amount >= FREE_SHIPPING_THRESHOLD:`. The finding names
  no concrete boundary value and gets no repair card. Rust and TypeScript
  resolve the equivalent constant. <!-- #4227 -->
- For TypeScript, the suggested discriminator for a changed return value or
  field can restate the changed expression instead of naming an independent
  expected value. <!-- #4216 residual after #4264 (b381d9a), which fixed

## Install

Cargo installation builds RIPR locally and requires Rust 1.95 or newer:

```text
cargo install ripr --version 0.11.0 --locked
```

RIPR's build MSRV is not a minimum compiler version for repositories analyzed
by an already-built release binary. Project verification continues to use the
target repository's selected toolchain.

- VS Code: install `EffortlessMetrics.ripr` from VS Marketplace or Open VSX.
- The VSIX, server manifest, per-target server archives, and checksums are
  distributed with the GitHub Release after their final verification.
