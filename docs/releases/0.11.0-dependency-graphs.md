### Unicode pin (#3788, #3789 re-evaluation)

`unicode-ident` stays at 1.0.24. `ra-ap-rustc_lexer` (through
`ra_ap_syntax` 0.0.349) const-asserts that `unicode-ident` and
`unicode-properties` share one Unicode version. `unicode-properties` 0.1.4 is
its latest release. Retried against this graph:

```text
unicode-ident 1.0.25 → error[E0080]: evaluation panicked: unicode-properties and
unicode-ident 1.0.26    unicode-ident must use the same Unicode version
                        error: could not compile `ra-ap-rustc_lexer`
```

Until this change the pin lived only in `Cargo.lock`. `cargo install ripr`
without `--locked` ignores the lockfile, so the packaged 0.11.0 crate resolved
1.0.26 and failed to compile. The pin is now `unicode-ident = "=1.0.24"` in
`crates/ripr/Cargo.toml`, enabled by the `lang-rust` feature that brings in
`ra_ap_syntax`. It is the only pin; there is no second lock-only workaround.

Removal trigger: a `unicode-properties` release on the same Unicode version as
current `unicode-ident`, or a selected `ra_ap_syntax` that drops the assert.
