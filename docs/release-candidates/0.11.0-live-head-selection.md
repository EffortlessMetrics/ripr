# RIPR 0.11.0 live-head release authority

Status: **active selection template, schema 1.1; no candidate is selected**.

Machine contract: [`0.11.0-live-head-selection.json`](0.11.0-live-head-selection.json).
Canonical decision: [#1609](https://github.com/EffortlessMetrics/ripr-swarm/issues/1609)
and [SPEC-0144](../specs/RIPR-SPEC-0144-release-control-lens.md#active-live-head-boundary).

The release candidate is exactly the accepted `ripr-swarm/main` commit at the
cut, with its complete reachable history. There is no candidate-only projection,
patch, squash, rebase, or tree-equivalent reconstruction. Historical hard-cut
and replacement receipts retain their original bytes and historical meanings.

## Template and admitted manifest

The template's candidate, range, prerequisite and pin fields remain null. It
cannot qualify an install, including when renamed or supplied with its own
correct digest. A schema-1.1 `pinned_exact_head` manifest binds one actual
candidate repository/SHA/tree/protected ref/package, exact package inputs,
the accepted #2766/#2768/#3807 packet bytes, ref readback/protection evidence,
and the selected proof inputs. Post-freeze executions stay `required_not_run`.

The selected-claim, denominator and audit owners decide their own predicates.
The manifest references their already accepted bytes; it does not grant them
acceptance by restating `passed`. #1609 must review and accept the complete raw
manifest digest independently of the producer. The direct #4510 input uses
that accepted digest explicitly. A locally generated sidecar, version string,
matching path, or template is not a substitute.

`source_parent` must remain null in this swarm manifest. Source #1769 reads
and binds the exact source parent only after swarm qualification. The final
source preflight/guarded join separately binds both parents and preserves all
history. No source hold or prediction is smuggled into swarm qualification.

## Existing execution boundary

The existing #4915 qualified `release-negative-corpus` command reuses its
source/archive/install/process custody. An explicit
`--candidate-manifest-sha256 <accepted-raw-sha256>` selects direct #1609 mode;
omitting that switch retains historical registry mode. Refusal in either mode
never retries or falls back to the other. No second installer or registry is
introduced. #3924's broader consumer-integration defer remains unchanged.

Before and after qualification, retain the current remote pin/ruleset readback.
The adapter checks retained exact bytes and source HEAD/tree/local ref, not an
authenticated or atomic hostile-host provenance guarantee. A moved ref or
changed manifest/input refuses. Unrelated later main movement never retargets
the immutable candidate.

JSON and the transaction handoff must render from the same pinned manifest.
Only final candidate execution can populate a separate qualification receipt.
A guided journey, synthetic blind-contract fixture result, selected agent row,
or unknown human observation cannot establish blind or universal usability.
