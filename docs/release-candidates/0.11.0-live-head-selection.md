# RIPR 0.11.0 live-head release authority

Status: **authority reset; transaction pin pending**

Machine-readable authority: [`0.11.0-live-head-selection.json`](0.11.0-live-head-selection.json).

## Selection rule

```text
0.11.0 candidate = the exact ripr-swarm/main commit selected at the release transaction boundary
```

The reset does not select a floating branch and does not construct candidate-only tree `T`. After this decision merges, the next release transaction records one exact `SWARM_PARENT`, creates one immutable ref pointing to that commit, and records the exact source parent separately.

The current transaction fields are intentionally null until the reset has merged. The later pin receipt must regenerate the merge base, all-reachable and first-parent counts, ordered swarm-range digest, open-PR dispositions, and required claims from the final heads. A missing or mismatched binding fails closed.

The pin receipt uses `refs/ripr/release-0.11.0-<SWARM_PARENT>`. Its ordered
range is `git rev-list --first-parent --reverse MERGE_BASE..SWARM_PARENT`; the
digest is SHA-256 over the exact UTF-8, newline-terminated SHA-list bytes. The
pin producer verifies that `origin` resolves to `EffortlessMetrics/ripr-swarm`.
Qualification and source preflight consume the exact
`SOURCE_PARENT`/`SWARM_PARENT`/`MERGE_BASE`/ref/digest tuple and fail closed on
missing or mismatched values.

## Superseded evidence

The 0.11.0 hard-cut receipt and July replacement-freeze receipt are retained as historical evidence of the authority that governed their transactions. Their historical claim content is preserved; the separate live-head authority records supersession. They no longer govern publication. The candidate-only C-to-T construction, T-bound denominator lock, and historical candidate refs are superseded for this release train.

## Scope boundary

- Once the exact live head is pinned, all work reachable from it is 0.11.0 content, including work previously listed under 0.11.1.
- Work not merged at the transaction boundary remains outside 0.11.0.
- `ripr/main` is held at one exact source parent before source preflight; routine maintenance does not silently move it.
- The reset authorizes neither source integration nor publication. Source `#1470` remains the publication boundary.
- 0.11.1 is re-baselined from the published 0.11.0 tree after closeout.

## Required pin receipt

The immutable pin that follows this reset must contain:

```text
SOURCE_PARENT
SWARM_PARENT
immutable ref
MERGE_BASE
all-reachable count
first-parent count
ordered swarm-range SHA digest
open-PR inventory and dispositions
version/toolchain
required claims and non-claims
```

The exact-head qualification and source preflight must consume those same values. Later swarm movement does not silently enter 0.11.0; repinning requires a release-invalidating proof failure and a new reviewed transaction.

After `SWARM_PARENT` is pinned, no further `ripr-swarm/main` merge enters
0.11.0 until the ancestry-preserving source release back-sync completes.
Development may continue on branches, but later merges belong to the next
release.

Source promotion must preserve the selected swarm commit graph as join parent
2. A tree-equivalent squash, rebase, cherry-pick, or reconstruction is a failed
promotion even when files are identical. The post-publication source-to-swarm
back-sync likewise preserves source release ancestry through a controlled merge
exception or other explicitly reviewed ancestry-preserving path.

The final pin receipt must re-audit verification behavior from the selected
tree. It must state what commands the CLI actually executes, what evidence it
emits, and whether it issues `RepairReceiptV2`; it must not copy forward the
historical blanket no-execution sentence. Regardless of execution behavior,
the release does not claim correctness, test adequacy, mutation adequacy,
requirement satisfaction, or merge safety.
