# Fixture Corpus: perl_packet_contract_migration

Spec: RIPR-SPEC-0064
Issue: #3217 (PR 1 of the #3216 Perl v2 consumer train)

## Given

A packet generated by the **real current producer** — `perl-ripr-facts` in
`EffortlessMetrics/perl-lsp-swarm` at commit
`a9664af790888333efbe50a042fa060f3cc2d171` (version 0.17.0) — for the
committed input workspace under `producer-inputs/ordinary_discount/`
(`lib/App/Discount.pm` + `t/discount.t` + `diff.patch`). The packet bytes,
input bytes, producer identity, and command are pinned in `corpus.json`.
This corpus is **not** hand-authored fixture evidence: both existing
`perl_lsp_facts_exporter` packets are compatibility-wrapper fixtures; the
packet here was emitted by the real batch exporter and is committed
byte-exact (`packet_sha256`).

## When

The migration-corpus validator (`cargo xtask check-fixture-contracts`) reads
`corpus.json`, verifies the packet and input digests against the committed
bytes, and requires every `required_contradiction_ids` row to exist in
`expected/contradictions.v1.json` with the typed row fields
(`json_pointer`, producer shape, consumer behavior, impact, class, v2
disposition, owner issue).

The focused consumer test
(`analysis::language::perl::tests::perl_packet_contract_migration_corpus_pins_real_producer_dispositions`)
feeds the committed packet through the production ingestion boundary with the
input directory as the analysis root, so the file-digest freshness check runs
against the committed input bytes, and pins the observed pipeline disposition
in `expected/consumer-dispositions.v1.json`.

The maintainer refresh command
(`cargo xtask perl-migration-refresh --producer-bin <path> [--case <id>]`)
re-runs the pinned producer command from a supplied producer binary and writes
a **candidate** packet plus a typed drift report under `candidates/`. It never
overwrites the accepted packet or the contradiction/disposition records;
promotion is a reviewed act that updates the corpus digest and the affected
records in the same change.

## Then

The committed packet must keep:

- byte-stable `packet_sha256` and per-input digests, so any packet or input
  edit without a reviewed corpus update fails the validator;
- decode result `ok` and structural validation `ok` through the current
  production ingestion boundary — including the packet-fingerprint
  recomputation, which empirically matches the real producer's recipe at the
  pinned commits;
- the pinned consumer disposition: one finding, exposure class `exposed`,
  `canonical_gap_emitted: false`, `repair_packet_ready: false`, advisory
  language limitation from `packet_status: "partial"`;
- all 13 contradiction rows, each classified as `implementation_defect`,
  `contract_change`, `fixture_correction`, or `unsupported_behavior`, with a
  typed impact (`decode | validation | identity | classification | output`),
  a v2 disposition, and an owning train issue.

Verified alignments observed at the pinned commits (documented here, not
contradiction rows): the fingerprint recipe matches; `packet_status` enum
semantics agree (`partial` accepted, fail-closed advisory); the Test2
framework vocabulary (`Test2::V0`/`Test2::V1`/`Test2::Suite`) is present on
both sides; relation referential integrity holds; the file digests bind the
committed input bytes.

## Must Not

This corpus must not imply v1 compatibility, a RIPR-owned Perl parser, live
LSP dependency, Perl runtime execution, package installation, test execution,
repair card, public badge contribution, default gate authority, RIPR Zero
authority, or stable Perl support-tier claim. It must not be normalized: the
committed packet is deliberately kept exactly as the real producer emitted it
(contradictions included) so later v2 PRs can use it as a shrinking oracle —
no fixture rewriting to make the current consumer happy.
